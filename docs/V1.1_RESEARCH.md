# v1.1：让这一口有个值得留意的地方

研究与编辑日期：2026-10-14。

本轮起点是一位用户的真实反馈：知道了酒标的故事，仍想知道眼前这杯该怎么喝、哪里值得留意。他希望得到像餐桌介绍那样的帮助，又不想听课本式品鉴。

多个 Agent 分别从产品、心理、普通用户旅程、精酿与服务，以及写作、主持、口头表达和社交内容角度研究与审查。这里的角色是分析视角，不是真人专家访谈。本轮没有做真人对照试饮，也没有证据证明这个版本会让人更喜欢一款酒。文本与发布检查另见 [验证记录](VALIDATION.md)；[v1.0 发布审查](RELEASE_REVIEW.md)保留作为历史记录。

## 改什么

“介绍一下这杯”默认得到一个容易做的观察和一句大白话解释。例如：

> 先闻一下，喝的时候比比闻着和入口的感觉。酒厂用果香来形容 Happy Hops；酒花能带来香，也能带来苦，闻着像水果不代表喝着甜。

这个例子结合了 [Russian River 的酒款描述](https://www.russianriverbrewing.com/brew/happy-hops-ipa/)与 [Sierra Nevada 的 IPA 介绍](https://sierranevada.com/style/ipa)。它没有声称眼前这一杯或这个用户一定有怎样的感受。酒花介绍也不是完整配料表，不能据此断言完全没有加水果。

我们考虑了三种结构：

| 方案 | 为什么选或不选 |
| --- | --- |
| 每次故事后加一套品饮说明 | 阅读变长；只想听故事的人也被安排看、闻、喝。不作为默认。 |
| 一个观察入口，按请求决定是否讲故事 | 只需记住一件能留意的事；解释本身也可以成为话头。作为 v1.1 默认。 |
| 连续问答的品饮教练 | 适合主动想深入的人；会占用更多手机时间。只在用户要求逐步带领时展开。 |

只要故事仍讲故事；只问怎么倒、太冰怎么办，先解决实际问题。说不喝、喝够或要开车，不加入尝饮动作。用户说没闻到或不喜欢，就沿着他的真实感受走。

## 各视角给出的约束

| 分析视角 | 对产品的具体要求 |
| --- | --- |
| 产品经理 | 宽泛的“介绍这杯”要提供杯中可体验的内容，不能只靠历史故事完成。 |
| 心理学 | 把注意到什么、如何描述、喜欢程度分开；避免引导用户报告预设答案。 |
| 普通用户旅程 | 看一次就知道可留意什么，不需要买器材、记流程或来回看手机。 |
| 精酿与服务 | 一次只选一个与已知酒款相关的维度；酒款未知时说明只是一般线索。 |
| 作家 | 写一个具体差别或因果，少用“馥郁、优雅、层次丰富”替代内容。 |
| 主持人 | 不点名朋友辨香，不用第二轮科普挽救一句“哦”；允许停下。 |
| 演讲者 | 留下一个动词和一件事，不让用户背六种水果与一串参数。 |
| 社交内容编辑 | 分享的价值来自小发现，不靠“全桌惊艳”“高手才懂”或口味等级。 |

这些约束形成 [品饮参考](../references/tasting.md)与 [输出示例](../templates/outputs.md)，并非每次回答都要向用户展示的清单。

## 研究支持到哪里

研究说明提示和环境可能改变预期或评价，但结果依条件而变。以下是对原始论文的简要归纳；“因此我们这样设计”属于本项目的推论，不是论文对本 Skill 的验证。

| 原始研究 | 观察到的结果与限制 | 本项目的设计推论 |
| --- | --- | --- |
| Blackmore、Hidrio、Yeomans，2022，87 位经常饮用啤酒的参与者 | 描述词影响某些属性评价；颜色和描述没有提高喜好评分。作者也讨论报告偏差。此次读取出版方摘要、Highlights 和可访问片段，未取得完整付费正文。[论文](https://www.sciencedirect.com/science/article/pii/S0950329322000374) | 观察线索可以帮助分配注意，但不宣传“讲一下就更好喝”，不把复述风味词当作发现。 |
| Reinoso Carvalho 等，2017，136 位参与者 | 深浅颜色改变饮前预期；饮后未观察到风味评分差异。一个未显著结果不能证明颜色永远没有作用。[原始全文](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2017.02205/full) | 不由颜色或酒标替用户宣布风味，也不把没感受到归因于不会喝。 |
| Lee、Frederick、Ariely，2006，三项实验 | 普通啤酒与加少量香醋的版本，提前披露信息与饮后披露产生不同偏好结果。这是特定实验，不能推广成任何介绍都会提升任何酒的体验。[原始全文](https://web.mit.edu/ariely/www/MIT/Papers/Beer.pdf) | 少给预先指定的味道，先给观察维度；已有的真实感受优先。 |
| Reinoso Carvalho 等，2016，231 位顾客 | 比较无标签、标签、标签加特定音乐的条件，报告味觉与愉悦评价受到影响。酒、音乐和场景均有特定条件。[原始全文](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2016.00636/full) | 社交环境值得尊重；朋友想聊音乐就聊音乐，不据此新增通用的音乐配酒处方。 |

专业品饮资料也不要求所有人套用同一流程。Cicerone 的方法文章强调目的不同，评估方法应相应变化，并提醒选择性知觉会让人忽略预期之外的感受。本项目据此选择少量线索和开放描述，没有照搬认证考试。[Cicerone：Tasting Methods for Beer Evaluation](https://www.cicerone.org/us-en/blog/tasting-methods-for-beer-evaluation)

## 怎样判断这一版有没有帮助

原来的两项验收继续保留：**能否放下手机，用自己的话讲；身边的人是否愿意接着聊。** 新增一项：**看完是否知道这一口可以留意什么。**

Agent 可以检查回答是否只有一个焦点、是否编造感受、是否尊重只要故事与不饮酒的请求。真实用户是否离开屏幕就能行动、是否觉得被考、能否自然分享，需要真人体验来确认。讲得长、记住了专业词、喝得更多，都不是成功指标。

后续可邀请少量不同经验、愿意参与的成年用户，用自己原本愿意饮用的酒试一次：读完收起手机，说说会留意什么，再按自己的意愿体验与交谈。分别记录“多留意到了什么”“是否更喜欢”“有没有压力”和双方是否愿意继续聊；不为测试要求多喝，不推测听者心理。这是尚未执行的可用性测试建议，不能当作已获得的效果证据。

欢迎把一次真实使用写进 [体验反馈](https://github.com/yanlin-zhou/beer-buddy/issues/new?template=experience.yml)。没有新发现、仍然觉得苦、没有接上话，同样能帮助我们改进。
