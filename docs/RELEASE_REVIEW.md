# v1.0.0 发布审查

2026-10-14。这里的角色是多 Agent 采用的分析视角，不代表九位真人专家背书。内容编辑、事实编辑、消费者审查与输出探针分工执行，主维护流程汇总修复。

两个核心问题贯穿全部取舍：**用户看完后，能否放下手机用自己的话讲？身边的人是否愿意接着聊？** 第一项需要离屏复述测试，第二项需要实际互动及听者反馈。此次先把能由文本和资料检查的问题解决，真人结果不冒充完成。

## 九个视角，具体改了什么

| 视角 | 原设计的风险 | v1.0.0 的处理与可检查证据 |
| --- | --- | --- |
| 传播学 | 记住术语不等于记住可转述的事；视频播放不等于现场愿意听 | 故事用人物、动作、物件承载信息；一次只给一个完整片段。见故事库中的保温箱、纸杯垫、塑料袋。 |
| 产品经理 | 场景模板覆盖明确意图；故事需求被选酒和品鉴截走 | `SKILL.md` 先判断用户此刻要做什么；只给一句、只记录等意图优先。README 提供免安装入口。 |
| 心理学 | “不能装、不能说我、必须递话”可能增加表现负担 | 接受苦、没闻出、不了解、安静和不喝；不从“哦”与看手机判断别人心理。这是产品风险判断，未测量心理效应。 |
| 社媒创作者 | 为吸引眼球补动机、假亲历；分享时丢掉事实限定 | 分享文本自包含，保留“酒厂说过／传说”；不夹带私密约会背景，不自动外发。 |
| 作家 | 知识点缺动作；为了生动编场面 | 12 条素材留可见物件和发生的事，不补人物内心与对话；口播默认两三句。 |
| 主持人 | 说完就考对方、强行每人参与；对方转场也拉回酒 | 问题可选；先接对方的音乐、食物和经历，允许停止；不饮酒者无需解释或尝酒。 |
| 演讲者 | 固定 20 字压坏经过；用户盯着手机背全文 | 取消死字数，需要练习时才给三个记忆词；短开头与完整版本不同时强推。 |
| 精酿知识审查 | 风格被当成单款保证；照片被当作质量诊断 | 修正 Hazy、鲜度、乳糖、泡沫、日期和采购量等 26 项审计问题；具体配方、市场标签与保存条件优先。 |
| 普通用户 journey | 首次使用难、说错难退场、结束又被安排下一杯 | 从发现、复制、首问、现场使用、不接话、分享、复用逐段检查；有直接例句、认错出口、纯记录与诚实记忆边界。 |

## 从公开社媒样本学到什么

上一轮研究检索了 B 站、抖音、Reddit 等公开内容。部分平台只取得搜索快照；没有取得足够可核验的小红书样本，因此不宣称覆盖全部中文社媒。下面仅保留对设计有用的例子，不把历史快照写成当前热度，也不把相关性写成传播原因。

- [袋装青岛啤酒的街头视频](https://www.bilibili.com/video/BV13d4y1D7QV/)提供人人看得懂的物件反差。设计推论是：日常生活可以先于风格分类。袋装习惯另用青啤及地方报道核验，不照抄视频中的起源解释。
- [精酿入门科普](https://www.bilibili.com/video/BV1bf4y1h7Rc/)说明有人主动选择长内容学习；它不证明朋友在酒桌上想听完整课程。因此保留按需学习能力，现场先给一个点。
- [“点 IPA 被当成势利眼”的讨论](https://www.reddit.com/r/beer/comments/1l4uuzz/does_anyone_else_get_treated_like_a_beer_snob_for/)暴露了为口味辩护、替别人判断品味的冲突。项目接受偏好，不从“精酿更高级”转成“普通啤酒才高级”。这是一组社区观察，不代表人群比例。
- [Coors 的 Mondays 品牌活动](https://www.molsoncoorsblog.com/coors-light-big-game-reaction-2025)把共同情绪变成可见包装。借鉴的是具体物件与生活经验；品牌自报增长和付费传播条件不用于承诺本项目效果。

## 交叉审查实际抓到的三个细节

1. 用户只说“苦”，旧示例却补了“还没找到喜欢它的地方”。现改为保留苦感，不替他决定喜不喜欢。
2. 故事卡标明官方自述，输出示例却遗漏这个限定。现已同步口播与资料。
3. 被纠正时无条件认错可能附和对方错误。现区分自己确实说错与双方尚未核实；承认前者，核对后者。

## 下一轮如何验证真正的收益

先邀请 8–12 位自愿试用者做问题发现，包含普通啤酒用户、精酿爱好者与不饮酒者；这不是能估计普遍效果的样本量。让每位用户选一个真实适配的场景，看一次答案后遮住屏幕，用自己的话复述。记录事实与限定是否保留、是否只能照念、哪句不像自己的口气。无需规定统一阅读秒数来替代表达质量。

实际用过后分开问：是否真的讲了、对方做了什么回应、用户自己的感受。听者体验只在听者自愿直接反馈时记录；未反馈人数与未知项保留。对方换话题、用户选择安静，都不自动算失败。明确拒绝后还追讲、复述时改编亲历或丢掉“传说”限定，才是需要优先修的问题。

内容转发、工具推荐、复访分别记录，不以续杯或喝得更多衡量留存。[当前已执行的检查](VALIDATION.md)和[体验反馈入口](https://github.com/yanlin-zhou/beer-buddy/issues/new?template=experience.yml)公开可查。
