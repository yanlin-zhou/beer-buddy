结果和实际回复可检查：[首轮 38 条](../evals/results/text-smoke.json)、[4 条定向复测](../evals/results/retests.json)、[8 条单文件入口](../evals/results/portable.json)。每次保存对应源文件 SHA-256。定向复测沿用原代理上下文；入口测试使用新 Agent，但每组内部仍是连续运行，不能写成全部独立会话。

首轮失败 S07 是对方追问“那本书后来怎么样”时，只重复起点并承认资料不足。现已补充吉尼斯官方后续：该书成为畅销书，却未回答最初的欧洲猎鸟问题，因为它关注世界纪录；复测能接住这个追问。smoke-12 原本给了可复制记录，却没有告诉用户下次带回；现补上这一操作说明并复测通过。

两项修改后未把全部 38 条重跑一次。未受影响条目保留首轮输出和源摘要；不能把不同批次混成一次“最终版全量 100% 通过”。评测状态字段在执行后更新，原判分使用的量表摘要保留在结果中；各条 must / must_not 未按答案放宽。

## 仍保留的五项部分符合

原量表没有被改成更容易通过：

- **S05**：解释“没闻到也正常”，但没提供量表要求的可选观察动作。用户只求确认是否不会喝，增加动作未必更合适；后续应先澄清量表。
- **S16**：正确说明 Hazy 不保证不苦，但没补具体产品核对、试饮或替代路径。没有推荐错误酒款；下一轮可检验是否给一个核对办法更实用。
- **S22**：给驾驶者提供故事且不推荐饮料，未再显式重复驾车提醒。原量表要求提醒，产品又要求避免无关模块，保留这处张力。
- **S25**：用户只限制“不能联网、别讲不确定故事”，回复确认限制，未另讲故事；量表却要求交付故事或承认未知。不能因此强迫每个设约束的用户听新故事。
- **S26**：提供葡萄酒聚会也能用的普通话题，没有虚构酒类知识，但未附“专业资料限啤酒”的声明。

这些是原量表的符合程度，不是五次真人社交失败。记录它们是为了下一轮改进与澄清，不能用重新命名来抬高本轮通过率。

## 尚未验证

- **真人离屏复述和听者体验**：没有试用者实验，无法报告自然度提升或聊天成功率。字数短、Agent 判断自然，都不能代替真人反馈。
- **真实照片识别**：S27–S30 没有附实际低光酒单、桌面和包装照片，未执行。文字“照片没传上来”与手抄酒单案例，仅验证文字诚实与指令边界，不算看图通过。
- **真实宿主端到端安装**：Claude 网页端、Cowork、Claude Code、Codex Skill 自动发现，以及 ChatGPT 等附件入口，未逐一实装验证。安装说明核对官方文档；单文件 Agent 读取不等于在这些产品中实测。
- **真实手机阅读和跨模型稳定性**：没有手机显示测试、用户阅读计时、跨模型多轮对比。运行环境未暴露可靠精确模型标识，结果如实写 unknown / inherited runtime，没有补写型号。
- **对照实验**：没有无 Skill 对照，也没有证据证明这些规则比普通提示词更有效。此前旧版输出不等于无 Skill baseline。
